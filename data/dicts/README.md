# Normalization dictionaries

One CSV per field, header `raw_value,code,method,reviewed`.

- `raw_value` is compared after `normalizeKey` (lowercase, ё→е, collapsed spaces, trailing `.,;:` removed), so case and trailing dots do not matter.
- `method`: `manual` (human-mapped), `rule` (generated by a rule script), `llm` (suggested by a model; keep `reviewed=false` until checked).
- Two rows whose raw values normalize to the same key must have the same code, or loading fails.
- A missing value is coded `unknown`; a value not listed here is coded `unrecognized`.

Code sets:
- `sex`: `m`, `f`
- `sentence_type`: `vmn`, `itl`, `vys`, `zak`, `pr`, `other`
- `birth_region`, `residence_region`, `source_region`: ISO 3166-2 subdivision codes for Russia (`RU-CHE`); ISO 3166-1 alpha-2 for other former Soviet republics (`UA`, `KZ`)
- `birth_country`: ISO 3166-1 alpha-2, plus `SU` for "USSR" when no republic is known
- `nationality`, `education`, `party`: lowercase ASCII slugs (`russian`, `incomplete_secondary`, `non_party`)

Grow a dictionary from the loaded data (after `pnpm etl import`):

```bash
pnpm etl values "пол" --dict sex
pnpm etl values "национальность" --dict nationality
pnpm etl values "образование" --dict education
pnpm etl values "партийность" --dict party
pnpm etl values "приговор" --dict sentence_type        # includes "приговор 1", "приговор 2", ...
pnpm etl values "место рождения" --first-segment --dict birth_region
pnpm etl values "место рождения" --first-segment --dict birth_country
pnpm etl values "место проживания" --first-segment --dict residence_region
pnpm etl values @category --dict source_region
```

`residence_region` is consulted first and falls back to `birth_region`, so add a row here only when the residence spelling is not already in `birth_region.csv`.

Rows with code `unrecognized` are candidates to add. Map the most frequent first, then re-run `pnpm etl normalize`.
